# proofgap

> 증명은 맞았는데 시스템이 틀린 곳을 찾는다.

**proofgap**은 체인에 배포된 ZK 검증 컨트랙트에서 **경계 결함**을 찾아내는 스캐너입니다. 경계 결함이란 증명 시스템은 설계대로 작동했는데, 그 바깥(셋업, 정산 로직, 검증 범위)이 잘못돼 생기는 결함을 말합니다. 결함이 있는 검증기를 찾으면, 그 검증기를 믿는 컨트랙트에 자산이 얼마나 묶여 있는지까지 함께 확인합니다.

> **상태: 단계 0 완료 (테스트 벡터 20개 전부 기대대로 판정).** `testvectors build`·`check`만 구현돼 있고, `scan` 등 나머지 명령어와 인터페이스는 계획입니다.

---

## 왜 만드는가

2026년 2월, Base의 프라이버시 풀 Veil과 Foom이 연달아 털렸습니다. 원인은 암호학이 아니었습니다. snarkjs 셋업의 Phase 2(회로별 무작위화)를 건너뛰어 검증키의 γ와 δ가 같은 값으로 남았고, 그 결과 검증기가 아무 증명이나 통과시키는 "도장"이 됐습니다. Foom은 Veil이 공개된 지 며칠 만에 같은 결함으로 털렸습니다.

이 결함은 검증키 상수만 보면 판정할 수 있습니다. 그런데도 복제 공격을 막지 못했습니다. 자동으로 찾아주는 도구가 없었기 때문입니다.

## 무엇을 하나

```
컨트랙트 수집 → 템플릿 분류 → 검증키 추출·정규화 → 규칙 판정
                                                        │ 탐지
                                                        ▼
       집계 통계 ◀─ 아니오 ─ 자산 있나? ◀─ 자금 노출 연결 ◀─ 로컬 재현
                              │ 예
                              ▼
                         비공개 제보 → 조치·유예 종료 후 개별 공개
```

1. **수집:** 이더리움·Base에서 소스가 검증된 컨트랙트를 모읍니다
2. **분류:** snarkjs Groth16 검증기 템플릿(신형·구형)을 식별합니다. 패턴이 맞지 않으면 수동 검토 대기열로 보냅니다
3. **추출:** 검증키(α, β, γ, δ, IC)를 뽑고 G2 좌표 순서를 정규화합니다
4. **판정:** 탐지 규칙을 적용합니다
5. **재현:** 로컬 포크에서 위조 증명이 실제로 통과하는지 확인합니다. 통과하지 않으면 오탐으로 처리합니다
6. **자금 연결:** 이 검증기를 호출하는 컨트랙트를 찾아 잔고와 권한(정지·업그레이드 가능 여부)을 확인합니다
7. **제보:** 자산이 묶인 건은 공개 전에 반드시 비공개로 제보합니다

## 탐지 규칙

| ID | 조건 | 심각도 | 상태 |
| --- | --- | --- | --- |
| R1 | γ == δ | 치명 | 단계 1 |
| R2 | δ == BN254 G2 기본 생성원 | 치명 | 단계 1 |
| R3 | 같은 δ가 서로 다른 회로의 검증기에서 재사용됨 | 정보 | 후보 |
| R4 | 공개 입력에 스칼라 필드 범위 검사가 없음 | 높음 (조건부) | 후보 |

**주의: γ가 생성원인 것은 정상입니다.** snarkjs는 γ를 G2 생성원으로 고정하고 Phase 2에서 δ만 무작위화합니다. "γ == 생성원"을 규칙으로 쓰면 정상적인 검증기가 전부 걸립니다. 자세한 내용은 [`docs/rules.md`](docs/rules.md)를 참고하세요.

| | 지금 하는 것 | 이후 단계 | 하지 않는 것 |
| --- | --- | --- | --- |
| 증명 시스템 | Groth16 (snarkjs 검증기) | PLONK, Halo2 | STARK 파라미터 평가 |
| 체인 | 이더리움, Base | Arbitrum, Optimism, Polygon, BNB | 비EVM 체인 |
| 입력 | 소스가 검증된 컨트랙트 | 소스 미검증 바이트코드 | 오프체인 검증기 |
| 결함 | 셋업 경계 | 정산 경계 휴리스틱 | 회로 제약 결함 자동 탐지 |

## 디렉터리 구조

```
proofgap/
├── scanner/        # 수집, 템플릿 분류, 검증키 추출·정규화
├── rules/          # 탐지 규칙 R1~R4
├── exposure/       # 호출자 탐색, 잔고 스냅샷, 권한 확인
├── testvectors/    # 정답을 아는 입력 (합성 양성·음성, 실제 사례)
├── repro/          # 로컬 재현 스크립트 (비공개, 공개 릴리스에서 제외)
├── dashboard/      # 내부 트리아지 화면, 공개 집계 통계
└── docs/
    ├── spec.md             # 프로덕트 명세서
    ├── rules.md            # 규칙별 조건, 근거, 오탐 주의점
    ├── troubleshooting.md  # 트러블슈팅 로그
    └── disclosure.md       # 디스클로저 절차
```

## 시작하기

필요한 도구:

- Node.js 24 이상: TypeScript를 빌드 없이 바로 실행합니다
- [circom](https://docs.circom.io/) 2.1 이상과 [snarkjs](https://github.com/iden3/snarkjs): 테스트 벡터 생성. snarkjs는 `npm install`로 신형(0.7.6)·구형(0.6.11) 템플릿용 버전이 함께 설치됩니다
- [Foundry](https://book.getfoundry.sh/): 로컬 재현
- 블록 탐색기 API 키 또는 [Sourcify](https://sourcify.dev/): 검증된 소스 수집
- 아카이브 노드 RPC: 호출자 탐색과 잔고 조회

```bash
npm install
npm link        # proofgap 명령어 등록 (또는 node bin/proofgap.ts ...)

# 테스트 벡터 생성과 규칙 검증
proofgap testvectors build    # 합성 벡터 재생성 + 체인 벡터 소스 수집 (circom 필요)
proofgap testvectors check    # 저장된 벡터만으로 판정 (npm test와 같음, 네트워크 불필요)

# 아래는 계획
# 단일 컨트랙트 검사
proofgap scan --chain base --address 0x...

# 전수 스캔
proofgap scan --chain ethereum --all
```

## 테스트 벡터

규칙은 정답을 아는 입력으로 먼저 검증합니다. 양성과 음성을 모두 갖춰야 오탐률을 잴 수 있습니다.

| 세트 | 내용 | 기대 결과 |
| --- | --- | --- |
| 알려진 양성 | Veil, Foom 검증기 | R1·R2 탐지 |
| 합성 양성 | Phase 2를 건너뛴 snarkjs 검증기 (신형·구형 템플릿) | R1·R2 탐지 |
| 합성 음성 | Phase 2 기여를 마친 같은 회로의 검증기 | 미탐지 |
| 실제 음성 | 공개 세레모니를 거친 알려진 프로토콜의 검증기 | 미탐지 |

## 책임 있는 공개

이 도구는 살아 있는 취약 컨트랙트를 찾을 수 있습니다. Foom은 Veil이 공개된 지 며칠 만에 같은 결함으로 털렸습니다. 그래서 아래 원칙을 지킵니다.

- **메인넷에서 자금을 움직이는 트랜잭션은 절대 보내지 않습니다.** 재현은 로컬 포크에서만 합니다. 화이트햇 구조가 필요하면 SEAL 911 같은 전문 조직에 넘깁니다.
- **자산이 묶인 취약 검증기는 비공개 제보가 먼저입니다.** 개별 주소는 조치가 끝나거나 유예 기간이 지난 뒤에만 공개합니다.
- **위조 증명 생성 코드는 공개하지 않습니다.** `repro/`는 공개 릴리스에서 제외합니다.
- **공개 통계는 집계 수치만 담습니다.** 스캔 수, 검증기 수, 규칙별 탐지 수, 자산 보유 건수가 해당됩니다.

절차는 [`docs/disclosure.md`](docs/disclosure.md)에 있습니다. 이 도구로 취약점을 발견했거나 저희 판정에 문제가 있다면 [`SECURITY.md`](SECURITY.md)의 경로로 연락해 주세요.

## 로드맵

- [x] **단계 0. 테스트 벡터:** 4개 세트가 모두 기대한 대로 판정됨
- [ ] **단계 1. 스캐너 코어:** 이더리움·Base 전수 스캔, 미분류 목록 확보
- [ ] **단계 2. 노출 연결:** 확인된 모든 건에 자산 유무 판정
- [ ] **단계 3. 트리아지·디스클로저:** 자산이 묶인 건 전부 제보 완료
